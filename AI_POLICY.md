# AI Contribution Policy
Today, AI tooling in the form of LLMs is being deployed in myriad ways from producing code to generating art - from autocompletion helpers to producing entire television channels. This wide range of output means that AI can be either a useful helper or a colossal burden to project maintainers. We, the H'uru project, value human contributors producing human art and human learning. We have a very small core team with very limited cycles for dealing with submissions. With this in mind, we are adopting this AI policy to emphasize our values of human contributions, human learning, and effective use of time.

## 1. Ownership
All changes submitted to H'uru projects are owned by their submitter. If you invent a new system, design a new feature, or make a fix, that is yours, and we expect you to maintain it. AI forgets everything it knows when its context is deleted. It is not acceptable to foist responsibility to or defer to the judgement of an AI.

If you submit a pull request that includes any AI generated content, you must
- understand every line of code in the submission.
- be able to explain why design decisions were (or were not) made during the review process.
- be able to explain the implementation during the review process.

AI agents may not submit pull requests under any circumstances. Humans review pull requests; therefore, the expectation is that humans will submit them. Further, do not post comments on issues or PRs that were generated by LLMs. The H'uru project is for human talk only.

## 2. Copyright and Legal
By submitting a contribution to the H'uru project, you acknowledge that you have the legal right to submit the contribution under the license of the repository. Most H'uru repositories are licensed under the GNU GPLv3 or variants thereof. If you cannot guarantee this, do not submit the contribution. The copyrightability of LLM generated content is still unclear in many jurisdictions.

## 3. Disclosure
If you used AI to generate any non-trivial part of your contribution, then you must disclose that in your submission. For pull requests, any AI generated code must be in its own commit, not intermixed with human created changes. All AI generated code must be noted using an `Assisted-by: <Name of Model>` trailer in the commit message.

For example:
```
Assisted-by: Claude Opus 5.5
```

Please note that limited autocomplete functionality, such as Visual Studio IntelliCode, does not need to be disclosed. These systems usually generate less than 15 lines of code at a time. The suggestions you accept should be the same code you would have written yourself.

## 4. Prohibited Uses
The following uses of AI are prohibited and will result in the pull request or contribution being immediately closed or otherwise dismissed
- using AI to write the content of a pull request description.
- using AI to write the content of an issue.
- using AI to write the content of a commit message.
- using AI to write documentation.
- using AI to write code comments.
- submitting large blocks of AI boilerplate.
- using AI to implement large systems requiring extensive design work and/or coordination as a drive-by.
- using AI to generate a substantial amount (or all) of a pull request's code.

## 5. Acceptable Uses
Many H'uru project developers have experimented with AI and used it as an aid. We encourage its use in some situations and call out these as specifically allowed cases
- autocompletion of small blocks of code, generally under 15 lines.
- translating your native, non-English language for the purpose of contributing to the project.
  - Please note that this does **not** include AI translations of game content.
- exploring unfamiliar code.
- reviewing code.
- debugging.

This list of acceptable cases is not exhaustive. As long as your use falls under our guidelines, it is likely acceptable.

## 6. AI Never Required
We value human contributors. AI generated code is infamously verbose and complex, and "vibe coded" projects often get to a point where only an AI can work on them. We do not want contributors to need an AI subscription or feel obligated to use AI tooling to work on H'uru projects. Declining most AI submissions helps us keep it that way.

## 7. Enforcement
The H'uru project maintainers may, at their own judgement, close or dismiss any pull request or other contribution that appears to be in violation of either the letter or spirit of this policy. When a maintainer suspects unacceptable use of AI, they are not required to provide any technical justification or entertain any rejoinders. Misrepresentation of AI generated content or continued violations may result in a ban from the project. We are a small project, and our time is best used collaborating with human contributors, not [meat proxies](https://dontbeameatproxy.com/). If you're concerned about your contribution being dismissed, open a discussion or contact a [maintainer](https://github.com/orgs/H-uru/people) to discuss your concerns before opening a pull request.
